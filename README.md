# kubesolo-nix

Nix package and NixOS module for [KubeSolo](https://github.com/portainer/kubesolo), a single-node Kubernetes distribution.

The package builds KubeSolo from source. The artifacts upstream embeds into the binary (containerd shim, crun, CNI plugins, CoreDNS and pause images) are pinned in [`pkgs/kubesolo/deps.json`](pkgs/kubesolo/deps.json) and match `build/download-deps.sh` at the packaged version. Supported platforms are `x86_64-linux` and `aarch64-linux`.

## Usage

```nix
{
  inputs.kubesolo.url = "github:<owner>/kubesolo-nix";

  outputs = { nixpkgs, kubesolo, ... }: {
    nixosConfigurations.edge = nixpkgs.lib.nixosSystem {
      modules = [
        kubesolo.nixosModules.default
        {
          services.kubesolo = {
            enable = true;
            openFirewall = true;
            settings = {
              network.nodeIP = "192.168.1.10";
              kubernetes.apiServer.extraSANs = [ "k8s.example.com" ];
            };
          };
        }
      ];
    };
  };
}
```

The admin kubeconfig is written to `/var/lib/kubesolo/pki/admin/admin.kubeconfig`. With `services.kubesolo.kubectl.enable = true`, the module installs a `kubectl` that uses it by default:

```sh
sudo kubectl get pods -A
```

## Options

| Option | Description |
|---|---|
| `services.kubesolo.settings` | Rendered to `/etc/kubesolo/config.yaml`. Accepts every key from the [upstream config file](https://github.com/portainer/kubesolo/blob/main/docs/configuration/config-file.md). The service restarts when it changes. |
| `services.kubesolo.environmentFile` | `KUBESOLO_*` variables kept out of the Nix store, such as `KUBESOLO_PORTAINER_EDGE_KEY`. They override `settings`. |
| `services.kubesolo.extraFlags` | Extra command-line flags. Deprecated upstream. |
| `services.kubesolo.kubectl.enable` | Installs a `kubectl` wrapper that sets `KUBECONFIG` to the admin kubeconfig unless it is already set. Use `services.kubesolo.kubectl.package` to pick the `kubectl` version. |
| `services.kubesolo.registries` | containerd registry mirrors, keyed by registry (`docker.io`, `ghcr.io`, `_default`, ...). See [Registry mirrors](#registry-mirrors). |
| `services.kubesolo.upgrade.healthTimeout` | Seconds a new KubeSolo version has to become healthy after a switch, default 600. See [Upgrades](#upgrades). |
| `services.kubesolo.openFirewall` | Opens TCP 6443 for the API server. |

The module also loads the required kernel modules, enables IP forwarding and adds `cni0` to `networking.firewall.trustedInterfaces` so pods can reach the API server and CoreDNS.

Notes:

- `settings.path` cannot be changed on an existing node; a new path starts a new cluster.
- The configuration API (`settings.api.enabled`) cannot persist changes, since the config file is generated by Nix. Upgrades and rollbacks over the API or `kubesoloctl` abort; see [Upgrades](#upgrades).
- To use a proxy, set `systemd.services.kubesolo.environment.HTTPS_PROXY` and related variables.

## Registry mirrors

```nix
services.kubesolo.registries = {
  "docker.io".mirrors = [ "https://mirror.example.com" ];
  "ghcr.io".mirrors = [ "https://mirror.example.com/ghcr.io" ];
};
```

Each entry becomes `/var/lib/kubesolo/containerd/registry/<name>/hosts.toml`, which containerd reads on every pull, so changes need no restart. `server` defaults to the upstream registry and is used when all mirrors fail; set it to `null` to disable the fallback. Use `settings` for anything else `hosts.toml` supports (`override_path`, `ca`, `header`, ...), and the name `_default` to cover every registry without its own entry. Images must be referenced by their fully qualified name. The images KubeSolo pulls at startup because they are not embedded (local-path-provisioner, Portainer agent, d2k) use these mirrors too; upstream pulls them directly, and the package patches this. See the [upstream documentation](https://github.com/portainer/kubesolo/blob/main/docs/configuration/registry.md).

## Upgrades

Restarting KubeSolo, after a configuration change or an upgrade, leaves the pods running and KubeSolo reattaches to them. When a switch changes the KubeSolo version, the module follows upstream's [in-place upgrade](https://github.com/portainer/kubesolo/blob/main/docs/configuration/upgrade-api.md):

1. Before switching, the new version opens a snapshot of the datastore. If it cannot, the switch aborts and the running version is untouched.
2. Before the new version starts, the datastore is backed up to `/var/lib/kubesolo/nixos-upgrade/backup`. One backup is kept.
3. The switch waits until the new version is healthy: the API server ready, the node Ready on the new version and a CoreDNS pod ready, for 30 seconds. If that does not happen within `upgrade.healthTimeout`, the switch fails.
4. Switching back to the previous version before the new one became healthy (`nixos-rebuild switch --rollback`) restores the datastore from the backup and restarts the pods. Changes made to the cluster under the new version are lost.

Once the new version has been healthy, switching back keeps the datastore and logs a warning, since an older API server can drop fields it does not know. With `nixos-rebuild boot`, steps 1 and 2 run when KubeSolo starts after the reboot, and a failed check keeps it from starting.

## Development

```sh
nix build .#kubesolo
nix flake check   # includes a NixOS VM test that boots a node and runs a pod
```

To update KubeSolo to the latest release, or to a given version:

```sh
nix run .#kubesolo.updateScript
nix run .#kubesolo.updateScript -- 1.2.2
```

The script regenerates `deps.json` from `build/download-deps.sh`, `types/const.go` and `go.mod` at the new tag, then runs `nix-update` for the version, source hash and `vendorHash`. It fails if `registry-hosts-for-image-pull.patch` no longer applies. Running it again at the same version re-pins the `portainer/pause:latest` image when upstream moves the tag. Check the result with `nix flake check`.
